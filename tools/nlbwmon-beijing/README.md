# nlbwmon: ImmortalWrt 25.12.2 x86/64 / 北京时间零点日切

构建目标：ImmortalWrt 25.12.2，r38135-0c4cd0f9920a，x86_64，musl，APK。
官方 SDK 与 SHA256、发布版 packages feed 和 nlbwmon 源码提交均固定在 sdk.lock.json。
包版本为 2025.06.02~29236be6-r100，属于本地定制补丁，不是厂商正式发行包。

## 修改范围

仅当固定周期为一天（YYYY-MM-DD/1）时，使用路由器本地日历日期作为统计周期。
路由器时区为 CST-8 / Asia/Shanghai 时，日切发生在北京时间 00:00。
这不会强制修改系统时区；其他时区按各自本地零点切换。
七天等多日固定周期及按月周期保持原逻辑。

保持数据库头部中的 type/base/value、源码提交及配置文件格式不变。
没有使用午夜重启、修改系统时间、清空数据库或更改现有统计数值的方式。

## 验证与构建

GitHub Actions 工作流负责 glibc 主机边界测试、原版缺陷检测、序列化头部对比、
多日/月周期回归、官方 SDK 编译、目标 ELF 依赖检查、目标 musl 测试。
测试通过不等于已在生产路由器完成跨午夜实测。

本地 Linux 可执行：
    bash tools/nlbwmon-beijing/test.sh
    bash tools/nlbwmon-beijing/build.sh

产物包含 APK、校验清单、SDK 锁定信息、ELF 检查和 musl 测试记录。
APK 是自行构建的软件包，不带官方软件仓库签名。应核对来源和 SHA256，
按本地包方式审查安装，不要关闭系统的全局签名验证。
只有 nlbwmon APK 属于交付目标，不要将构建目录里的依赖包或内核模块一起升级。

## 安装与历史过渡

本仓库和工作流不会连接路由器或自动安装产物。部署前必须另行备份：
- /etc/config/nlbwmon；
- 当前全部持久统计数据库，以及正在运行的周期；
- 原 nlbwmon 包或可回退的程序与所需资料。

配置应保持 database_interval='2026-10-08/1'、database_generations='100'、
现有 database_directory 和本地网段。上游默认配置仍为原样；
安装时必须保留路由器已有配置，不要直接覆盖成软件包默认设置。

历史文件的日期标签可继续使用，但其原始统计范围仍是 08:00 到次日 08:00，
不能重新解释为零点到零点，也不能从汇总值中精确拆出凌晨八小时。
建议在当天 08:00 之后部署，避免新旧代码对当前日期判断不同。
部署后的首个周期可能缩短（例如从08:00到24:00），需注明过渡，
之后才是完整自然日。没有自动重算或搬移历史文件。

若必须保留完全清晰的新旧统计边界，应在单独备份旧库后为新零点统计使用独立目录，
而不是将两种时间范围的历史汇总混合后宣称已转换。
